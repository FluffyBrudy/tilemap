⚠️ Final Corrections (Small but Important)
1. Missing Validation of base_path

Right now you load:

base_path = Path(config["base_path"])

But you don’t validate it.

Required addition:
if "base_path" not in config:
    raise RuntimeError("Invalid settings.json: missing 'base_path'")

base_path = Path(config["base_path"]).expanduser()

if not base_path.is_absolute():
    raise RuntimeError("base_path must be absolute")

# Optional but recommended:
base_path = base_path.resolve()
Why this matters:
Prevents corrupted or hand-edited configs from breaking silently
Enforces your “deterministic” rule at runtime, not just design level
2. Ensure base_path Is Not Inside Package / .venv

You stated this as intent, but it’s not enforced.

Add guard:
import sys

venv_path = Path(sys.prefix).resolve()

if venv_path in base_path.parents:
    raise RuntimeError("base_path cannot be inside virtual environment")
Why:

Prevents exactly the class of bugs you’re trying to eliminate.

3. Clarify: Editor Writes ONLY Under base_path/data

Right now you say:

“All user data written under base_path/”

That’s slightly loose.

Tighten to:

All user-generated data MUST be written under:

base_path / "data"

No exceptions. No top-level writes.

4. Standalone Tools – One Edge Case

You wrote:

“They can accept user-provided paths via command-line”

That’s fine—but here’s the constraint you should explicitly add:

If a standalone tool is given a path, it must treat it as opaque input and must NOT attempt to infer or resolve project structure (e.g., must not assume presence of data/ or settings.json).

This prevents accidental coupling later.

5. settings.json Location Strictness

You currently enforce:

Path.cwd() / "settings.json"

Good—but add one explicit rule:

No upward directory search (no parent traversal).

Otherwise someone will try to “improve” it later.

read settings.json
