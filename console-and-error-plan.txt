# Tilemap Editor - Console & Error Handling Plan

## PART 1: DESIGN RULES (From Previous Documents)

### From pathrefactor.txt
- Internal modules MUST NOT read settings.json
- Standalone tools continue using BASE_PATH (internal default)
- Editor is the ONLY component allowed to read settings.json
- User data lives under <base_path>/data/

### From issue.txt
- BASE_PATH is strictly internal-only
- Internal modules must NOT access user config

### From logconfig-instruction.txt
- R6: No internal module (standalone.py etc.) may read or depend on settings.json

### From final-instruction.txt
- R10: Standalone tools must treat user-provided paths as opaque and must NOT infer project structure

### From logconfig-improved.txt
- ErrorHandler has zero knowledge of BASE_PATH
- ErrorHandler initialized via dependency injection from Editor
- log_root = base_path / data_path / "logs"

---

## PART 2: CURRENT PROBLEMS

### Problem 1: Error Console Not Functional
- Error console shows empty because it uses BASE_PATH for log file
- Editor writes logs to project data_root, but error console looks at BASE_PATH
- ErrorHandler uses dependency injection correctly (writes to project data_root)
- BUT standalone error_console.py looks at wrong path

### Problem 2: Swallowed Errors in standalone.py
When module import fails (e.g., missing thorpy, numpy, PIL):
- Only generic "Module not found" is logged
- Actual ImportError details are lost
- User sees unhelpful error message

Example from logs:
```
[INFO] str: Module not found: plugins.tileset_collision.standalone
```
Actual error was: `No module named 'thorpy'` → `No module named 'numpy'` → `No module named 'PIL'`

---

## PART 3: SOLUTION PLAN

### Fix 1: Error Console Uses Correct Log Path

**Design Rule**: Standalone tools must NOT infer project structure

**Solution**: Error console should NOT try to find project logs. Instead:
- Editor passes log file path directly to error console when launching
- Or error console reads from a shared location that Editor writes to

**Implementation**:
- Add `--log-file` argument to standalone_error_console.py
- Editor passes correct project log file path when launching
- Error console displays that specific file's content

```python
# In editor.py when launching error console:
log_file = self.data_root / "logs" / "errors.log"
args = ["--window-size", window_size, "--log-file", str(log_file)]
```

### Fix 2: Un-swallow Hidden Errors

**Design Rule**: R10 - Standalone tools must treat user-provided paths as opaque

**Current Problem**: standalone.py catches exceptions but loses details:
```python
except ModuleNotFoundError:
    error_handler.capture(f"Module not found: {module_name}", severity="info")
```

**Solution**: Log actual exception details before catching:

```python
except ModuleNotFoundError as e:
    error_handler.capture(
        f"Module not found: {module_name} - {type(e).__name__}: {e}",
        severity="info"
    )
```

This preserves the chain: `ModuleNotFoundError: No module named 'thorpy'`
